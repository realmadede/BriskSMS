AUTHENTICATION & SECURITY SPECIFICATION

Webhook signature verification.

BriskSMS delivers event notifications with an X-Brisk-Signature header. Every incoming webhook payload must be validated using constant-time timing-safe comparison to prevent timing attacks.

TypeScript (Node.js / Bun Verification Contract) HMAC SHA-256 
// Verified signature verification contract from @brisksms/shared
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifyWebhookSignature(
  rawPayload: string,
  expectedSignature: string,
  secret: string
): boolean {
  const computed = createHmac('sha256', secret)
    .update(rawPayload, 'utf8')
    .digest('hex');

  const computedBuf = Buffer.from(computed, 'hex');
  const expectedBuf = Buffer.from(expectedSignature, 'hex');

  if (computedBuf.length !== expectedBuf.length) {
    return false;
  }

  // Timing-safe comparison prevents timing side-channel leaks
  return timingSafeEqual(computedBuf, expectedBuf);
}
RESPONSIBLE PRACTICES

Developer security standards.

Payment reconciliation and communication infrastructure requires strict security invariants.

Tenant Isolation

Every transaction query and mutation is partitioned by Organization ID. Cross-tenant leakage is strictly prevented at the database and API gateway level.

Deterministic Idempotency

All webhook actions and service integrations must include idempotency keys to ensure duplicate network transmissions never result in double settlement.

Purpose-Limited Scope

Relay devices only ingest authorized financial notifications from verified providers (M-Pesa, Mixx, Airtel Money, HaloPesa, supported banks). Personal messages are rejected.

Audit Logging

Every administrative access, API request, and reconciliation decision is immutably appended to tenant audit records.
