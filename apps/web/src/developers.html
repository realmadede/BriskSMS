CORE ARCHITECTURE

Engineered for financial correctness.

BriskSMS enforces strict tenant isolation, cryptographic deduplication, and immutable audit logs on every payment event.

Non-Custodial Flow

BriskSMS never holds customer funds or acts as a payment escrow. You retain 100% control over your bank and carrier merchant accounts.

SHA-256 Deduplication

Every transaction is hashed across organization, provider, amount, reference, and timestamp. Duplicate network retries never trigger double-settlement.

Deterministic Settlement

Rule-based invoice matching eliminates guessing. Underpayments, overpayments, and ambiguities automatically route to human review.

Carrier Relay Sync

Authorized Android relays collect push notifications from M-Pesa, Tigo Pesa, Airtel Money, Halotel, and CRDB Bank with battery and signal monitoring.

SPECIFICATION

Standard HTTP status & error codes.

All API errors return consistent JSON responses with machine-readable error codes and human-readable resolution instructions.

HTTP Status Error Code Meaning Recovery Action
200 OK SUCCESS Request executed and ledger updated. Proceed with downstream business fulfillment.
400 Bad Request INVALID_PAYLOAD Missing required fields (e.g. amount, reference). Verify request body matches schema definition.
401 Unauthorized AUTH_KEY_EXPIRED Invalid or expired API bearer token. Rotate and generate a new key in Developer Settings.
409 Conflict DUPLICATE_IDEMPOTENCY Request with this idempotency key already processed. Fetch the original transaction ID instead of re-submitting.
422 Unprocessable UNPARSED_SMS_FORMAT Notification does not match any authorized provider template. Route to Manual Review queue for engineer inspection.
429 Too Many Requests RATE_LIMIT_EXCEEDED Exceeded allowed requests per minute on your plan. Implement exponential backoff or upgrade your tier.
